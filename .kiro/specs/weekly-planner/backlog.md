## 1. 미해결 결정 (논의 중)

### 1.1 시간 입력 단위 — 1분 vs 5분
- **현재 상태**: 1분 단위 (시/분 드롭다운, 분 00~59).
- **고민**:
  - 1분: 정밀하지만 분 드롭다운 옵션이 60개라 길다.
  - 5분: 빠르고 짧지만 `14:37` 같은 값은 못 넣는다.
- **후보 대안**:
  - (a) 분을 텍스트로 직접 입력 허용 + 검증
  - (b) 5분 기본 + "직접 입력" 토글로 미세조정
  - (c) 자주 쓰는 프리셋(00/30) 빠른 버튼 + 드롭다운 병행
- **결정**: 보류. 실제 사용 패턴 보고 결정.

### 1.2 지난 미완료 항목 처리 (2026-08-06 논의 시작)
- **문제**: 날짜가 지났는데 완료되지 않은 항목이 그 날짜 셀에 그대로 남아
  묻힌다. "다시 보여주거나 별도 표시" 또는 "다른 날짜로 이동"이 필요해 보임.
- **고민할 지점**:
  - 표시만 할지(예: 매트릭스에 "지난 미완료 N건" 배지, 별도 사이드 패널)
    vs 실제로 데이터를 이동시킬지(날짜 재할당) — 후자는 "그 항목이 원래
    언제 계획됐었는가" 기록을 잃는 트레이드오프가 있음.
  - 이동한다면 자동(예: 오늘로 매일 굴려줌)인지 수동(사용자가 드래그/버튼으로
    옮김)인지 — 자동은 "왜 계획이 계속 밀리는지" 인식을 방해할 수 있음.
  - 반복 항목(아직 미구현, 7-B)과 개념이 겹칠 수 있어 그쪽 설계와 같이 고려.
- **결정(2026-08-06)**: 표시 우선 + 상세 패널에서 선택적 이동. 데이터는
  건드리지 않고(원래 계획일 유지) 헤더에 "지난 미완료 N건" 배지만 띄우고,
  목록에서 항목을 클릭하면 매트릭스가 그 항목이 있는 주로 이동해 상세
  패널을 연다. 실제로 날짜를 옮기고 싶으면 상세 패널에서 직접 바꾼다(자동
  이동 없음 — "왜 계속 밀리는지" 인식을 가리지 않기 위해).
- **구현 완료(2026-08-06)**:
  - `api/items.ts`에 `listOverdueItems(beforeDate)` 추가(`date < beforeDate
    AND done = false`, 현재 조회 범위와 무관하게 전체 기간 조회).
  - `hooks/useOverdueItems.ts` — 위 쿼리를 감싸는 훅. `done`/`date`가 바뀌는
    패치, 삭제 후에 `MatrixPage.tsx`에서 명시적으로 `reload()`를 호출해
    배지 수를 최신 상태로 유지.
  - `components/OverdueBadge.tsx` — 헤더에 배지, 클릭 시 드롭다운 목록
    (날짜·내용·카테고리). `CategoryFilter.tsx`와 동일한 바깥 클릭 닫기
    패턴.
  - `ItemDetailPanel.tsx` — 헤더의 읽기 전용 날짜 텍스트를 `<input
    type="date">`로 교체해 처음으로 항목 날짜를 직접 바꿀 수 있게 됨(이전엔
    날짜를 바꿀 방법 자체가 없었음). 이 기능이 "선택적으로 옮기기"의
    실질적인 경로.
  - 스키마 변경 없음. 브라우저 인증 흐름 때문에 dev 서버 기동 확인까지만
    하고 실제 클릭 테스트는 못 함 — 화면에서 확인 필요.

### 1.4 피드백 확인 방법 — 관리자 계정 vs 대안 (2026-07-27 논의 시작)

    변경 0, 지금 바로 가능.
  - (b) **가벼운 앱 내 조회(추천)**: `feedback` select 정책에 본인 UID 예외를
    추가(`auth.uid() = owner_id or auth.uid() = '<내 UID>'`) + 설정 탭에 본인

    작은 목록 컴포넌트로 해결.
  - (c) **역할 테이블**(`admin_users` 등)로 정식 관리자 개념 도입 — 지금
    규모엔 과함, 비추천.
  - (d) **알림형**(피드백 insert 시 이메일/슬랙으로 통지) — Database Webhook +
    Edge Function 필요(서버 코드 최초 도입 명분). 지금 단계엔 오버킬.
- **결정**: (b) 채택, 구현 완료(2026-07-27). 리터럴 UID를 public 레포에 커밋하지
  않기 위해 처음엔 `current_setting('app.admin_uid', true)` 세션 GUC로 구현했으나,
  Supavisor 커넥션 풀러가 기존 커넥션을 재사용해 새 GUC가 반영 안 되는 문제
  (관리자 계정에서도 피드백 0건으로 보임)를 발견 → `app_settings` 테이블 +
  `is_admin()` security definer 함수로 교체(매 쿼리마다 실제로 읽으므로 풀링과
  무관). 실제 값은 `app_settings` 테이블과 `VITE_ADMIN_UID` 환경변수에만 존재.
  `handoff.md` 2장/7장 참고.

## 2. 낙서장 발전 로드맵

현재 낙서장 = 목록 + 제목/본문 편집 + 저장/삭제 (최소 형태). 단계적으로 확장.

- **1단계 — 탐색·정리 (저비용, 즉효) — 완료(2026-08-06)**
  - 검색: 제목·본문 키워드 필터 (클라이언트 필터, 서버 변경 없음)
  - 정렬 옵션: 최근 수정순 / 제목순 토글
  - 고정(pin): 자주 보는 메모 상단 고정 (`notes.pinned bool` 1컬럼 추가,
    검색/정렬 결과와 무관하게 항상 최상단). ⚠️ `schema.sql` 대시보드 재실행
    필요.
  - **UX 다듬기(2026-08-06, 실사용 피드백 반영)**: 초기 이모지(📌/🔒/🔓)가
    너무 크고 눈에 띄어 흑백 SVG 아이콘(회색 톤, `PinIcon`/`LockIcon`)으로
    교체. 고정 아이콘은 고정된 메모에만 상시 노출, 고정 안 된 메모는 목록
    항목에 마우스를 올렸을 때만 나타남(항상 다 보이면 산만함). 비공개
    (`hide_preview`) 토글은 목록 행에서 편집기 상단(제목 입력 옆)으로
    이동 — 잠긴 메모가 아닌데도 자물쇠가 다 보여서 헷갈린다는 피드백,
    목록엔 이미 제목 아래 "🔒 비공개" 텍스트로 상태가 보이므로 별도 버튼은
    중복이라 판단. **진입 시 자동 선택 제거**: 낙서장 탭에 들어가자마자
    첫 메모 내용이 바로 보이는 게 프라이버시상 별로라는 피드백 — 이제 목록만
    보이고 메모를 클릭해야 내용이 열림(카카오톡 태블릿 버전과 유사한 느낌).
- **2단계 — 구조화**
  - 태그: `notes.tags text[]` + 태그 필터 (항목 참가자 태그 패턴 재사용)
  - 연결 메모 통합 뷰: 항목에 묶인 메모를 한곳에서 훑는 옵션 탭
- **3단계 — 표현력 (규모 큼, 나중)**
  - 리치 텍스트(3.1 참조)
  - 메모 간 링크, 이미지 첨부(Supabase Storage 필요)
- **추천 시작점**: 1단계(검색 + 정렬 + 고정). 가볍고 체감 효과 큼 — "쌓아두는 곳 → 찾아 쓰는 곳".

### 2.4 비공개성 · 되돌리기 · 자동저장 (2026-07-27 논의 시작)
현재 낙서장 목록은 제목+본문 미리보기가 그대로 노출되고(`NotesPage.tsx` 목록
버튼 안에 `n.body` 스니펫 표시), 저장은 수동 버튼/Ctrl+Cmd+S뿐이라 되돌리기가
없다. "실수로 본문을 지우고 그대로 저장돼버렸다"는 피드백에서 나온 후속 과제.

- **목록 미리보기 숨기기 — 완료(2026-07-27, 메모별 선택형으로 수정)**: 처음엔
  전체 메모의 미리보기를 일괄 제거했으나, "메모마다 선택하고 싶다"는 피드백으로
  범위 변경 — 기본은 기존처럼 본문 스니펫 노출, 메모별로 자물쇠 토글 버튼을
  눌러 숨기면(`notes.hide_preview bool`) 목록에 본문 대신 "🔒 비공개"만 표시.
  **주의**: 지금은 UI 표시만 가리는 것이고 서버측 암호화는 아니다(대시보드
  Table Editor나 다른 방법으로 열람 시 그대로 보임).
  - **향후 후보**: 숨긴 메모를 4자리 PIN으로 실제 암호화(지금 당장은 아님,
    2026-07-27 논의). 하려면 클라이언트 사이드 암호화(예: PIN에서 유도한 키로
    body를 암호화해 저장) 방식이 필요 — PIN을 서버에 평문으로 두면 의미가
    없고, PIN을 잊으면 복구 불가라는 트레이드오프도 미리 알려야 함.
    (2026-08-06: "비밀메모가 좀 더 실용적이었으면" 피드백 — 지금은 UI만
    가리는 수준이라 실제 암호화 없이는 "실용성"이 크게 안 느껴질 수 있음을
    시사. PIN 암호화 착수 시점을 앞당길지 재논의 필요.)
- **폴더 계층 — 결정(2026-07-27), 구현 완료(2026-08-06)**: 지금은 "폴더 없음"
  또는 "1단계 폴더"만 지원(하위 폴더 없음). 다만 나중에 트리로 확장할 여지를
  남기기 위해 스키마는 처음부터 트리 대응 형태로 만든다 — `note_folders`
  (id, owner_id, name, sort_order, is_archive, `parent_id uuid null
  references note_folders(id)`) 테이블 + `notes.folder_id`(소유자까지
  검증하는 복합 FK로 처음부터 생성 — `items.category_id` 때 단일 FK로
  만들었다가 나중에 복합으로 바꾸느라 겪은 재실행 문제를 반복하지 않기
  위해). 지금 UI는 `parent_id`를 항상 null로만 써서 평평한 목록만
  노출하고, 트리 UI(하위 폴더 펼치기 등)는 나중에 `parent_id`를 실제로
  쓰기 시작하면 됨.
  - **보관(archive) 통합 — 결정(2026-08-06): 폴더와 함께 설계**. 별도
    `archived bool` 컬럼 대신, `note_folders.is_archive bool`로 표시된
    특수 폴더 하나(사용자당 최대 1개, 부분 unique 인덱스로 강제)를
    "보관함"으로 취급 — 로그인 후 낙서장 진입 시 없으면 자동 생성
    (`ensureArchiveFolder()`, `ensureDefaultCategory()`와 같은 지연 생성
    패턴). 목록 필터 "전체"는 보관함에 속한 메모를 제외하고, "보관함"을
    선택해야 보임. 메모를 보관함으로 옮기는 것도 일반 폴더 이동과 동일한
    UI(편집기 상단 폴더 select)로 처리 — 별도 "보관" 버튼 없음.
  - **구현 요약**: `api/noteFolders.ts`(list/create/remove/ensureArchive),
    `NotesPage.tsx`에 폴더 칩 목록(전체/커스텀폴더들/보관함/+폴더) +
    편집기 상단 폴더 이동 select. 폴더 삭제는 소속 메모를 지우지 않고
    `folder_id`만 해제(app 레이어에서 삭제 전 unlink). 폴더 이름 변경은
    아직 없음(후속 과제). **⚠️ `schema.sql` 대시보드 재실행 필요**
    (`note_folders` 테이블 + `notes.folder_id`).
  - **버그 수정 1차(2026-08-06)**: `schema.sql` 재실행 전 상태에서 낙서장에
    들어가면 기존 메모가 전부 안 보이는 회귀 발견 — 메모 목록 조회
    (`listNotes()`)와 보관함 준비(`ensureArchiveFolder()`)를 `Promise.all`로
    묶어놨던 탓에, `note_folders` 테이블이 아직 없어 `ensureArchiveFolder()`가
    실패하면 메모 조회까지 통째로 실패했음. 두 조회를 분리해 폴더 쪽이
    실패해도 메모 목록은 항상 뜨도록 수정.
  - **버그 수정 2차(2026-08-06)**: 1차 수정 후에도 여전히 메모가 하나도
    안 보인다는 재현 보고 → 진짜 원인은 "전체" 필터 로직이었음. "보관함이
    아닌 메모만 보이기"를 `n.folder_id !== archiveFolder?.id`로 비교했는데,
    보관함 정보가 아직 로드되지 않았거나(`archiveFolder`가 `null`) 아예
    `note_folders` 테이블이 없으면 `archiveFolder?.id`가 `undefined`가
    되고, 대부분의 메모는 `folder_id`가 `null`이라 `null !== undefined`가
    `true`처럼 보이지만 실제로는 정규화(`?? null`) 여부에 따라 `null`끼리
    비교되어 `false`로 걸러지는 경우가 생겼음(데이터 삭제 아님, 순수 표시
    로직 버그). `archiveFolder`가 실제로 존재할 때만 그 id와 비교하고,

## 3. 보류된 기능

### 3.1 메모 서식 (리치 텍스트)
- **현재**: 기본 저장 단축키(Ctrl/Cmd+S)만. 텍스트 서식 없음.

- **트레이드오프**: 의존성 1개 추가. 낙서장·연결 메모 양쪽에 영향.
- **대안 후보(2026-08-06 제안)**: 마크다운 문법 그대로 저장 + 렌더링(WYSIWYG
  아닌 텍스트 편집 + 미리보기/렌더 전환). TipTap보다 가볍고 의존성도 작지만
  "타이핑하며 바로 보이는" 경험은 약함. 노션처럼 무거워지는 걸 원치 않으면
  이쪽이 더 낙서장 성격에 맞을 수 있음 — 방향 결정은 보류.

### 3.2 좁은 AI (Edge Function)
- 자연어로 항목 추가(예: "내일 3시 팀미팅"), 주간 회고 요약 등 경계가 뚜렷한 기능.

### 8.1 즉시 처리 (실사용 UX 문제)

  `loadedIdRef`로 "실제로 `selectedId`가 바뀐 경우"에만 리셋하도록 수정.

  `MatrixGrid`의 `min-w-[760px]`). 데스크톱 전용으로 지어져 모바일에서는
  "축소된 데스크톱"으로 보이던 것. viewport 메타는 정상이었다.
  "낙서장 목록이 복잡하다"와 모바일 문제는 **같은 문제**여서 함께 처리했다 —
  좌측 컬럼의 조작 줄이 그대로 모바일 화면 상단을 전부 먹고 있었다.
  - **모바일 주간 뷰 — 축 전치 시도 후 세로 목록으로 교체(2026-08-09)**:
    카테고리×날짜 2차원이 390px에 안 들어간다. 후보는 (a) 가로 스크롤 유지,
    (b) 하루 뷰, (c) 축 전치였고 **처음엔 (c) 채택** — 좁은 화면에선 열이 적은
    쪽(카테고리 4~6개)을 가로로 두는 게 낫다는 판단이었다. `MatrixGrid`에
    `transposed` prop 하나로 구현(셀 내용이 (카테고리, 날짜)에만 의존해 루프만
    뒤집으면 됨).
    - **실기기 확인 결과 실패 → 교체**. 전치는 **열 개수**만 줄였고 **열 폭**은
      그대로였다. 390px에서는 열이 몇 개든 칸당 65~90px가 상한인데 항목
      텍스트는 150px쯤 있어야 읽히므로, 축을 어느 쪽으로 놔도 한 줄이 짧게
      접힌다. **격자를 유지하는 한 폰에서는 해결이 안 되는 문제**였다.
    - **최종: `components/WeekAgenda.tsx`** — 격자를 버리고 각 셀을 전체 폭
      블록으로 펼친 세로 목록. 날짜가 구분 헤더, 그 아래 **항목이 있는
      카테고리만** 나열(빈 칸까지 그리면 7일 × 카테고리 수만큼 빈 줄이 생김).

      다르다. 세로 스크롤로 주 전체를 훑는 것도 유지.
    - **추가 흐름의 차이**: 격자는 셀을 탭하면 카테고리가 자동으로 정해지지만
      목록은 날짜만 정해지므로 카테고리 select를 함께 띄운다. 직전에 고른
      카테고리를 기억해 연속 입력에서 매번 다시 고르지 않게 했다. 닫기 버튼도
      뒀다 — 격자는 blur로 닫히지만 폰에서는 키보드가 올라온 상태라 blur
      처리가 들쭉날쭉하다.
    - `MatrixGrid`의 `transposed` 분기는 **되돌려 제거**했다(죽은 코드 방지).
      데스크톱 격자는 원래대로.
    - **실기기 재확인(2026-08-09)**: 목록 형태로 잘 동작함을 확인. "나쁘지 않되
      나중에 개선 여지 있음"으로 남겨둔다(구체적 불만은 아직 없음).
      **카테고리 선택 드롭다운은 현재 방식이 최선**이라고 확인됨 — 대안으로

  - **`lib/useMediaQuery.ts` 신설**: 색·여백·줄바꿈은 Tailwind 브레이크포인트로
    처리하고, 이 훅은 **DOM 구조가 달라지는 경우에만** 쓴다(축 전치는 표의
    행/열을 뒤집는 것이라 CSS로는 불가능). 기준은 Tailwind `md`(768px)와 동일.
  - **D-day 배너 — 결정: 뷰 헤더 줄에 합치기**. 배지로 접는 안도 있었으나
    "상시 눈에 보이게"라는 원래 취지와 충돌해서 기각. 주/월 이동 버튼·날짜
    라벨이 있는 줄의 남는 공간에 인라인으로 넣어(`ViewHeader`의 children 슬롯)
    줄 하나를 통째로 아꼈다.
    - **수정(2026-08-09, 실기기 확인)**: 처음엔 좁은 화면에서도 그냥 `flex-1`로
      뒀는데, 날짜 라벨·뷰 토글과 남는 폭을 나눠 가져 **글자를 읽을 수 없었다**.
      좁은 화면에선 `basis-full`로 자기 줄을 통째로 쓰게 고침. `order-last`를
      같이 준 이유 — 없으면 배너가 먼저 줄을 차지해 뷰 토글이 세 번째 줄로
      밀려난다. 넓은 화면은 `md:flex-1 md:basis-auto`로 원래대로 인라인.
  - **낙서장 모바일**: 예전엔 목록과 편집기가 세로로 쌓여서, 메모를 고른 뒤
    목록 전체를 지나 아래로 스크롤해야 편집기가 나왔다. 좁은 화면에선 한 번에
    하나만 보이도록 바꾸고(`선택 있음`=편집기, `없음`=목록) 편집기 상단에
    "‹ 목록" 버튼을 넣었다.
  - **낙서장 목록 밀도**: 조작 줄이 4줄(새 메모 / 폴더 칩 / 검색 / 정렬)이었다.

    월간 달력 셀 높이를 모바일에서 낮춰(`h-20 md:h-24`) 한 화면에 더 들어가게 함.

- **토글 UI 개선 — 완료(2026-08-09)**: 기존 스위치는 색만 바뀌어(회색↔남색)
  어느 쪽이 켜진 상태인지 흘긋 봐서는 알기 어려웠다. 공용
  `components/Toggle.tsx` 신설 — 구분 수단은 (1) 손잡이 위치(꺼짐=왼쪽,
  켜짐=오른쪽), (2) 트랙 색 + 꺼짐 상태의 또렷한 테두리 두 가지.
  `ItemDetailPanel.tsx`의 "D-day로 표시"·"상단 배너에 고정" 두 토글을 이걸로
  교체(`size` md/sm, `onColor`만 다름). 앞으로 새 토글은 전부 이 컴포넌트를 쓴다.
  - **1차 시안에서 버린 것 2가지 (사용자 확인 후)**: (a) 옆에 "켬"/"끔" 글자를
    붙였으나 불필요하다는 피드백으로 제거 — 손잡이 위치만으로 충분.

    안 깨진다. 손잡이 지름은 트랙 높이 − 여백(2px×2) − 테두리(1px×2)에 맞춤

    확인하고, 문구에 **무엇이 함께 사라지는지 구체적으로** 나열
    ("세부 체크리스트 3개 · 메모도 함께 삭제됩니다"). 아무것도 안 딸린 항목은
    바로 삭제. 필요한 정보는 `subtaskCount`(부모의 `subtaskProgress`에서)와
    `hasNote`(`ItemNote`에 새로 단 `onHasBodyChange` 콜백)로 패널에 내려준다.
  - **서브태스크 삭제**: 확인 신규 추가 — 단 **미완료 줄에서만** 묻는다.

  - 카테고리·메모·폴더 삭제는 기존 확인창 유지(연쇄 삭제라 항상 물어야 함).
  - **남은 질문**: 사용자가 "너무 쉽다"고 느낀 지점이 정확히 어디였는지 미확인.
    위 두 곳으로 해결됐는지 화면에서 확인하고, 아니라면 그 지점을 특정해 추가.

  (1.3 "회원가입·계정 관리 보안 강화"와 같은 주제 — 그쪽으로 통합)
- **관리자 뷰어**: 지금은 설정 탭의 `FeedbackList`(피드백 조회)뿐. 확장에
  따라 데이터 요약/통계까지 포함한 관리자 화면이 필요해짐. 우선순위 자체는
  높지 않으나 사용자가 늘면 필수.

### 8.4 면밀한 검토 후 진행 (착수 전 설계 필요)
- **데이터베이스 기능 추가**: 범위 미정.
- **하위 계층 캘린더**: 와인 리스트 기록 같은 용도 — 평소에는 특정 요소를
  숨겨두고 별도로 펼쳐 보는 계층. 낙서장 폴더(`note_folders.parent_id`, 지금은
  항상 null)와 개념이 겹칠 수 있어 같이 설계하는 게 나을 듯.

### 8.6 PWA — 완료(2026-08-09, v4.0.0)
`vite-plugin-pwa` 도입. 설치형(홈 화면 추가) + 앱 셸 오프라인.

- **오프라인 범위 — 결정: 앱 셸까지만**. 이 앱은 데이터가 전부 Supabase에
  있어 오프라인이면 조회가 안 된다. 그래도 셸을 캐시해두면 브라우저의 "연결
  없음" 화면 대신 **앱이 정상적으로 뜨고 데이터 영역만 안내로 대체**된다
  (지금은 오프라인에서 아예 아무것도 안 뜸). Supabase 요청은 교차 출처라
  precache/navigateFallback 규칙에 애초에 안 걸리므로, 오래된 데이터가 최신인
  척 보일 위험이 없다.
  - **후속 과제(사용자 요청): 마지막 조회 데이터까지 읽기 전용 캐시**로 확장.
    지금 구조는 데이터 조회 계층을 안 건드렸으므로 서비스 워커 런타임 캐시
    규칙만 추가하면 된다. 다만 착수 전에 같이 정해야 할 것 — (1) "언제 받아온
    데이터인지" 화면 표시, (2) 무효화 규칙, (3) `hide_preview`로 가려둔
    비공개 메모가 기기에 평문으로 남는 문제.
- **업데이트 — 결정: 자동 적용**(`registerType: 'autoUpdate'` +
  `registerSW({ immediate: true })`). 혼자 쓰는 개인 도구라 "새 버전 있음"을
  물어볼 이유가 적고, 배포했는데 폰에서만 옛 화면이 남는 일을 막는다.
- **아이콘**: `@vite-pwa/assets-generator`로 기존 `public/favicon.svg`에서
  생성(`pwa-assets.config.ts`, `npx pwa-assets-generator`로 재생성). 결과물은
  커밋해두고 로고가 바뀔 때만 다시 돌린다.
  - iOS는 매니페스트의 `icons`를 읽지 않아 `index.html`에 `apple-touch-icon`
    링크를 직접 넣어야 한다. 없으면 홈 화면 아이콘 자리에 화면 캡처가 뜬다.
  - **기본 프리셋은 배경을 투명하게 두는데**, maskable·apple 아이콘은 OS가
    모양을 잘라내며 합성하므로 투명하면 런처/iOS에서 검게 깔릴 수 있다.
    두 종류만 흰 배경(`background_color`와 동일)으로 다시 생성했다. `any`
    용도인 `pwa-*.png`는 투명 그대로가 맞다.
  - **보안 메모**: 이 생성기가 끌고 오는 `sharp` 구버전에 libvips CVE 4건
    (high)이 있어 `package.json`의 `overrides`로 `sharp@^0.35.3`을 강제했다.
    `vite-plugin-pwa`의 optional peer라 빼려 해도 자동으로 딸려 온다.
- **오프라인 안내**: `lib/useOnline.ts` 신설. 셸이 뜨는 상태에서 데이터 조회
  실패를 평소 문구("데이터를 불러오지 못했습니다")로 보여주면 앱이 고장난
  것처럼 읽혀서, 오프라인일 때만 문구를 바꾼다(`MatrixPage`·`NotesPage`).
  `navigator.onLine`은 "랜에 붙어 있는가"만 알려주므로 문구 전환에만 쓰고
  조회 성공 판단에는 쓰지 않는다.
- **남은 audit 4건은 이번 작업과 무관한 기존 것** — `nanoid`, `postcss`,
  `react-router`(RSC 모드 CSRF, 이 앱은 RSC 미사용). `npm audit fix`로
  해결 가능하나 급하지 않아 뺐다(2026-08-10 사용자 결정).

### 8.7 설치 권장 배너 — 완료(2026-08-10, v4.0.1)
"다른 사이트처럼 접속 시 설치 안내가 떴으면" 요청. 크롬 계열은 설치 가능해지면
`beforeinstallprompt`를 쏘는데 기본 UI가 주소창 구석 아이콘이라 잘 안 보인다.
그 이벤트를 가로채 보관해두고(`prompt()`는 사용자 제스처 안에서만 호출 가능)
자체 배너를 화면 아래에 띄운다 — `components/InstallPrompt.tsx`.

- **잔소리가 되지 않도록 지킨 선**: 이미 설치돼 standalone 으로 실행 중이면
  아예 안 띄움 / "나중에" 또는 설치창 거절 시 14일 스누즈(localStorage) /
  로그인 후에만 노출(처음 들어온 사람에게 설치부터 권하지 않음) /
  이벤트가 안 오는 브라우저(iOS 사파리 등)에서는 아무것도 안 띄움 —
  설치 방법을 글로 안내하는 건 묻지 않은 사용자에게 잔소리라 하지 않는다.

### 8.8 홈 화면 위젯 — 조사 결과(2026-08-10), 착수 전 결정 필요
"위젯도 추가하고 싶다" 요청에 대한 사실 정리.

- **PWA로는 안드로이드 홈 화면 위젯을 만들 수 없다.** 웹 API가 없다.
  매니페스트의 `widgets` 멤버는 **Windows 11 위젯 보드** 전용 스펙이라
  안드로이드와 무관하다(Adaptive Cards 필요). 지금 가치 없음.
- **진짜 위젯 = 네이티브 작업**: Capacitor(또는 TWA) 셸 + Kotlin
  `AppWidgetProvider`. 위젯은 웹뷰를 쓸 수 없으므로 **Supabase를 직접 호출하는
  별도 데이터 경로**(토큰 보관 포함)를 따로 만들어야 한다. Android Studio·JDK
  빌드 환경, 서명, 배포 경로까지 딸려온다. 7-C의 "홈 위젯(가장 비쌈)"과 동일.
- **지금 바로 되는 대안 — 앱 바로가기(`shortcuts`)**: 홈 화면 아이콘 롱프레스
  메뉴("낙서장", "오늘 항목 추가" 등). 매니페스트 몇 줄. 위젯처럼 정보를
  띄워주지는 못하지만 "홈에서 한 번에 들어간다"는 목적은 상당 부분 충족.
- **결정(2026-08-10): 둘 다 미룸.** 앱 바로가기도 지금은 넣지 않는다. 위젯이
  필요해지면 위 조사 결과를 그대로 출발점으로 삼으면 된다.
