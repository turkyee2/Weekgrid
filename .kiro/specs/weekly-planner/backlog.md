## 1. 미해결 결정 (논의 중)

### 1.1 시간 입력 단위 — 1분 vs 5분
- **현재 상태**: 1분 단위 (시/분 드롭다운, 분 00~59).
- **고민**:
  - 1분: 정밀하지만 분 드롭다운 옵션이 60개라 길다.
  - 5분: 빠르고 짧지만 `14:37` 같은 값은 못 넣는다.
- **후보 대안**:
  - (a) 분을 텍스트로 직접 입력 허용 + 검증
  - (b) 5분 기본 + "직접 입력" 토글로 미세조정
  - (c) 자주 쓰는 프리셋(00/30) 빠른 버튼 + 드롭다운 병행
- **결정**: 보류. 실제 사용 패턴 보고 결정.

## 2. 낙서장 발전 로드맵

현재 낙서장 = 목록 + 제목/본문 편집 + 저장/삭제 (최소 형태). 단계적으로 확장.

- **1단계 — 탐색·정리 (저비용, 즉효)**
  - 검색: 제목·본문 키워드 필터 (클라이언트 필터, 서버 변경 없음)
  - 정렬 옵션: 최근 수정순 / 제목순 토글
  - 고정(pin): 자주 보는 메모 상단 고정 (`notes.pinned bool` 1컬럼 추가)
- **2단계 — 구조화**
  - 태그: `notes.tags text[]` + 태그 필터 (항목 참가자 태그 패턴 재사용)
  - 연결 메모 통합 뷰: 항목에 묶인 메모를 한곳에서 훑는 옵션 탭
- **3단계 — 표현력 (규모 큼, 나중)**
  - 리치 텍스트(3.1 참조)
  - 메모 간 링크, 이미지 첨부(Supabase Storage 필요)
- **추천 시작점**: 1단계(검색 + 정렬 + 고정). 가볍고 체감 효과 큼 — "쌓아두는 곳 → 찾아 쓰는 곳".

## 3. 보류된 기능

### 3.1 메모 서식 (리치 텍스트)
- **현재**: 기본 저장 단축키(Ctrl/Cmd+S)만. 텍스트 서식 없음.
- **방향**: TipTap 헤드리스 에디터.
  - 굵게 / 기울임 / 밑줄 / 취소선, 글자색 4~5 프리셋, 크기 3단계, 불릿·체크리스트
  - `notes.body`를 HTML로 저장 → 기존 평문 메모는 그대로 텍스트로 표시(하위호환)
  - CSV 내보내기는 항목 content만 쓰므로 영향 없음
- **트레이드오프**: 의존성 1개 추가. 낙서장·연결 메모 양쪽에 영향.

### 3.2 좁은 AI (Edge Function)
- 자연어로 항목 추가(예: "내일 3시 팀미팅"), 주간 회고 요약 등 경계가 뚜렷한 기능.
- API 키 보호 위해 Supabase Edge Function 필요(프론트에 키 금지) → 백엔드 첫 도입 명분.
- 지금 데이터가 구조화(시간·참가자·서브태스크)돼 있어 나중에 붙이기 쉬움. 당장은 안 함.

## 4. 운영/유지보수 메모

### 4.1 공휴일 데이터 갱신
- `src/lib/holidays.ts` 정적 데이터셋. **2024~2027**은 음력(설날·추석·부처님오신날)·대체공휴일 포함, **2028~2030**은 양력 고정공휴일만.
- 음력·대체공휴일은 매년 바뀌므로 관보/공공데이터포털 확인해 연도별로 추가·보정 필요.
- 대안(향후): 공공데이터 API + 캐시, 또는 음력 계산 라이브러리.

### 4.2 스키마 마이그레이션 적용 대기
- `items.accent`(중요도 색) 컬럼 — Supabase SQL Editor에서 실행해야 저장됨:
  `alter table items add column if not exists accent text;`
- 원칙: 스키마 변경 시 `supabase/schema.sql`에 idempotent 구문으로 추가하고 대시보드에서 재실행.

### 4.3 대량 데이터 페이지네이션
- `listAllItems`(CSV) / `listNotes`는 전체 조회 → 데이터 누적 시 PostgREST 기본 반환 행 제한에 걸릴 수 있음.
- 향후 range 헤더 기반 페이지네이션 보강.

## 5. 아키텍처/방향성 논의 요약 (참고)

- **보안**: 사용자 간에는 RLS로 격리되지만, 프로젝트 소유자(운영자)는 평문 DB 열람 가능.
  "운영자도 못 봄" 수준이 필요하면 클라이언트측 E2E 암호화가 별도 과제(검색·가공 포기 트레이드오프 큼).
- **정체성/차별점**: 시간 슬롯 중심의 구글/기본 캘린더와 달리 **카테고리×날짜 매트릭스**가 핵심.
  정면 경쟁(알림·초대·회의)보다 매트릭스 + 심층 할일 + 메모 결합으로 차별. 구글 캘린더는
  "동기화" 대신 "읽어와 겹쳐 보기(오버레이)"가 승산 있음.
- **앱/위젯**: PWA(가장 쌈) → Capacitor(웹 재활용 앱) → 네이티브 위젯(가장 비쌈) 순.
  현재 Supabase API 중심 구조는 나중에 위젯이 데이터를 가져오기에 유리.
